# Android 权限与系统限制说明

本文回答两个问题：**清屏需要什么权限？为什么有些事 Android 不允许做？**

---

## 1. 核心权限：无障碍服务

### 1.1 它不是普通运行时权限

清屏的核心组件 `AdGuardService` 继承 `AccessibilityService`，在 Manifest 中声明：

```xml
<service
    android:name=".guard.AdGuardService"
    android:exported="true"
    android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE">
    <intent-filter>
        <action android:name="android.accessibilityservice.AccessibilityService" />
    </intent-filter>
    <meta-data
        android:name="android.accessibilityservice"
        android:resource="@xml/accessibility_service_config" />
</service>
```

`BIND_ACCESSIBILITY_SERVICE` 是**服务级权限**，由系统持有，第三方应用不能自己给自己授权。用户必须在：

> 设置 → 无障碍 → 已下载的应用 → 清屏 → 开启「清屏守护」

手动开启。应用只能跳转到这个设置页，**不能代码自动开启**，也不能绕过确认弹窗。

### 1.2 配置里实际使用的能力

`accessibility_service_config.xml` 中：

| 配置 | 作用 | 风险 |
|---|---|---|
| `canRetrieveWindowContent="true"` | 读取当前窗口的节点树、文字、contentDescription、控件类型 | 能看到其他应用的界面文字 |
| `canPerformGestures="true"` | 在节点不可点击时，用 `dispatchGesture` 点按坐标 | 可以模拟点击 |
| `flagIncludeNotImportantViews` | 扫描到更多非重要视图 | 提升识别率，也增加遍历量 |
| `flagRetrieveInteractiveWindows` | 获取交互窗口 | 需要读取窗口 |
| `typeWindowStateChanged` | 前台 Activity 变化 | 误触检测的基础 |
| `typeWindowContentChanged` | 页面内容变化（倒计时、广告出现） | 触发扫描 |
| `typeViewClicked` | 用户点击事件 | 辅助判断误触 |
| `typeTouchInteractionStart/End` | 触摸交互起止 | 部分 ROM 可能不派发 |

没有申请：
- `SYSTEM_ALERT_WINDOW`（悬浮窗）：本方案不需要，悬浮窗也无法可靠拦截其他应用的触摸。
- `PACKAGE_USAGE_STATS`（使用情况访问）：不需要，无障碍事件已能拿到前台包名。
- `INTERNET`：**完全没有**，所以统计无法上传。

### 1.3 Android 13+ 的「受限设置」

侧载应用在 Android 13 及以上开启无障碍时，可能被系统拦截，提示「为了安全，此设置当前不可用」。需要：

> 应用信息 → 右上角 ⋮ → 允许受限设置

然后重新进入无障碍设置开启。这个限制是系统针对侧载应用的安全策略，应用无法绕过。

### 1.4 Google Play 政策

Google Play 对 `AccessibilityService` 的用途有严格限制，主要面向残障辅助功能。用无障碍 API 自动跳过其他应用的广告，通常会被认定为不符合政策，存在下架风险。  
**建议侧载分发，不要上架 Play。**

## 2. 其他权限

| 权限 | 类型 | 用途 | 不给会怎样 |
|---|---|---|---|
| `QUERY_ALL_PACKAGES` | 普通权限（安装时） | 读取已安装应用名称、图标，用于按 App 统计和跳转名单 | 只能显示包名，部分应用可能不可见 |
| `RECEIVE_BOOT_COMPLETED` | 普通权限 | 开机后恢复可选的前台守护通知 | 开机广播不生效；无障碍服务本身仍可能被系统重新绑定 |
| `POST_NOTIFICATIONS` | Android 13+ 运行时权限 | 显示常驻守护通知 | 前台服务仍可运行，但通知可能不可见；状态提示变弱 |
| `FOREGROUND_SERVICE` | 普通权限 | 运行 `GuardForegroundService` | 无法使用常驻通知保活 |
| `FOREGROUND_SERVICE_SPECIAL_USE` | Android 14+ 普通权限 | `specialUse` 类型前台服务 | Android 14+ 启动前台服务会失败 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 普通权限（敏感） | 弹出系统「忽略电池优化」对话框 | 无法直接弹对话框，只能跳到电池优化列表 |
| `BIND_ACCESSIBILITY_SERVICE` | 服务级系统权限 | 绑定无障碍服务 | 核心功能完全不可用 |

### 关于 `QUERY_ALL_PACKAGES`

Android 11 引入包可见性限制。清屏需要把包名显示成应用名/图标，因此声明了 `QUERY_ALL_PACKAGES`。  
如果上架 Google Play，这个权限需要提交使用说明，且审核严格；侧载没有这个问题。

### 关于电池优化

`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 在 Google Play 上也属于敏感权限。清屏只在用户主动点击「电池优化」时弹系统对话框，不会静默申请。

## 3. Android 版本差异

| 版本 | 影响 | 清屏的应对 |
|---|---|---|
| Android 8.0–10 | 前台服务、后台限制相对宽松 | 支持，minSdk 26 |
| Android 11 | 包可见性限制；无障碍可读取窗口 | 声明 `QUERY_ALL_PACKAGES` |
| Android 12 | 后台启动前台服务受限；无障碍服务受系统管理 | 只在应用前台或 `BOOT_COMPLETED` 时启动前台服务；无障碍由系统绑定 |
| Android 13 | 通知运行时权限；侧载受限设置 | 请求通知权限；引导「允许受限设置」 |
| Android 14 | 前台服务必须声明类型 | 使用 `specialUse` + `FOREGROUND_SERVICE_SPECIAL_USE` |
| Android 15/16 | 更严格的后台/前台服务限制；部分 ROM 更激进杀进程 | 依赖系统重新绑定无障碍服务 + 电池白名单；不能保证 100% |

## 4. 为什么不能「点击前拦截」

Android 的输入分发顺序是：

```text
触摸事件 → 系统 InputDispatcher → 目标应用窗口 → 应用代码处理
```

普通应用（包括无障碍服务）**没有**全局输入过滤器。`AccessibilityService` 能：
- 读取窗口内容；
- 执行 `ACTION_CLICK`；
- 执行 `GLOBAL_ACTION_BACK`；
- 用 `dispatchGesture` 模拟点击。

但它**不能**：
- 在触摸事件到达目标应用前拦截或改写；
- 阻止某个 Activity 被 `startActivity` 启动；
- 监听其他应用的传感器（摇晃广告）；
- 修改其他应用的网络请求（除非使用 VpnService）。

所以「误触跳转广告」只能做成**事后返回**：目标页面先启动，服务收到 `TYPE_WINDOW_STATE_CHANGED`，确认目标是名单内的购物/浏览器 App，再按返回键。用户会看到短暂闪屏，这是系统限制导致的，不是实现缺陷。

## 5. 为什么不能保证点到所有开屏广告

`AccessibilityNodeInfo` 只暴露应用愿意暴露的节点。以下情况会失败：

1. **纯图片按钮**：没有 `text`，也没有 `contentDescription`。
2. **WebView 内部 DOM 不暴露**：部分 App 的 H5 广告只能看到外层 WebView。
3. **Canvas / Flutter / Unity 自绘**：整个页面可能只有一个节点。
4. **`FLAG_SECURE` 窗口**：系统禁止截屏/读取内容（银行、支付类常见）。
5. **动态混淆文案**：不是「跳过」，而是「关闭」「X」或图标；只能靠广告标记 + 兜底规则，可能失败或误点。
6. **倒计时未结束**：按钮 `enabled=false` 时不会点，等下一次内容变化再试。

本版**没有**使用截图 OCR，原因是：
- Android 11+ 的 `takeScreenshot` 有频率限制；
- 离线中文 OCR 会增加包体、耗电和延迟；
- 截屏涉及更高隐私敏感度；
- 很多广告在 WebView 中，OCR 仍可能受限于分辨率/动画。

如果后续要增强，建议做成**显式开关**，只在开屏保护期内、本地识别、不保存图片。

## 6. 开机自启与后台存活

### 6.1 无障碍服务的特殊性

只要用户在系统设置中保持「清屏守护」开启，**系统会在开机后重新绑定无障碍服务**，不需要清屏的主界面进程一直活着。这是最可靠的「开机自动运行」来源。

### 6.2 开机广播

`BootReceiver` 监听：
- `BOOT_COMPLETED`
- `MY_PACKAGE_REPLACED`
- 部分 ROM 的 `QUICKBOOT_POWERON`

如果守护开启、无障碍已启用，会启动 `GuardForegroundService` 常驻通知。它不能替代无障碍服务，只是提升进程优先级和显示状态。

### 6.3 为什么不能保证

- **强行停止（Force Stop）**：Android 会把应用置于 stopped 状态，所有广播、服务、Job 都不会运行，直到用户再次打开应用。任何第三方应用都无法绕过。
- **厂商省电策略**：小米/华为/OPPO/vivo 等可能冻结或杀死后台；需要手动允许自启动、后台运行、关闭省电限制。
- **Doze / 应用待机**：深度 Doze 会延迟后台任务；前台服务和无障碍服务通常不受影响，但不绝对。
- **用户关闭无障碍**：服务立即停止，应用无法自动重新开启。

### 6.4 本项目采取的保活措施

1. 无障碍服务由系统绑定，不依赖 Activity。
2. 可选 `specialUse` 前台服务 + 低优先级常驻通知。
3. `START_STICKY`，系统回收后尝试重建。
4. 开机/应用更新广播恢复通知服务。
5. 引导用户忽略电池优化、设置厂商自启动。

这些措施是**提高概率**，不是**保证存活**。文档和 UI 都不应承诺 100%。

## 7. 隐私边界

| 数据 | 是否读取 | 是否保存 | 是否上传 |
|---|---|---|---|
| 当前窗口节点文字 | 是（瞬时） | 只保存命中的按钮文字 | 否 |
| 屏幕截图 | 否 | 否 | 否 |
| 前台应用包名 | 是 | 是（统计） | 否 |
| 应用名称/图标 | 是 | 名称保存，图标不落盘 | 否 |
| 点击/跳转时间 | 是 | 是 | 否 |
| 网络请求 | 无 `INTERNET` 权限 | — | 否 |

无障碍服务天然能读取屏幕内容，这是系统机制。清屏的代码只做按钮文字匹配、包名判断和统计写入，没有网络代码路径。

---

## 8. 分发建议

- **个人使用**：直接安装 debug APK，开启无障碍即可。
- **小范围分发**：生成自己的 release keystore，签名后分发；提醒用户 Android 13+ 的受限设置。
- **应用商店**：不建议。无障碍自动化 + 广告跳过通常不符合商店政策；如坚持上架，需要准备详细的辅助功能说明、隐私政策和权限用途，且仍可能被拒。
