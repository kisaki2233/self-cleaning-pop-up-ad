# 清屏：设计与实现

## 1. 目标与边界

### 目标

1. 在其他 App 的开屏页自动点击「跳过」「关闭广告」。
2. 对误触导致的跳转，尽快返回原 App。
3. 按 App 统计成功拦截次数，并在应用内查看。
4. 尽可能开机自动恢复，减少后台清理导致失效。
5. 本地运行，不收集/上传数据。

### 非目标

- 不是网络层广告拦截器。
- 不拦截应用内信息流、Banner、激励视频广告。
- 不绕过 Android 的权限模型，不要求 root。
- 不保证在所有 ROM、所有广告 SDK 上 100% 成功。

## 2. 总体架构

```text
┌────────────────────────────────────────────────────────┐
│ UI 层                                                   │
│  MainActivity        首页：状态、总览、按 App 统计       │
│  SettingsActivity    启动时长、点击延迟、名单、保活       │
│  AppPickerActivity   搜索/勾选跳转目标 App               │
└───────────────┬────────────────────────────────────────┘
                │ Prefs (SharedPreferences) / StatsDb (SQLite)
┌───────────────▼────────────────────────────────────────┐
│ 守护层                                                  │
│  AdGuardService (AccessibilityService)                  │
│    ├─ ForegroundTracker   前台包名与进入时间             │
│    ├─ SplashScanner       节点遍历、文案识别、点击       │
│    └─ JumpGuard           目标名单、返回、二次确认       │
│                                                         │
│  GuardForegroundService  可选 specialUse 前台通知        │
│  BootReceiver            开机/更新后恢复通知服务         │
└────────────────────────────────────────────────────────┘
```

### 为什么全部用平台 API

- 不引入 AndroidX / Compose / Room / Kotlin：构建体积小，依赖少，离线可编译。
- SQLiteOpenHelper 足够存事件；RecyclerView 换成 ScrollView + LinearLayout，统计行数有限（最多 200）。
- 平台 `Switch`、`SeekBar`、`AlertDialog` 减少兼容性问题。

## 3. 开屏跳过实现

### 3.1 事件入口

`AdGuardService.onAccessibilityEvent` 处理：

- `TYPE_WINDOW_STATE_CHANGED`：前台 Activity 变化。
- `TYPE_WINDOW_CONTENT_CHANGED`：页面内容变化，可能广告刚加载/倒计时刷新。
- `TYPE_VIEW_CLICKED`、`TYPE_TOUCH_INTERACTION_START`：记录最近交互，用于「非开屏期」的误触判断。

### 3.2 作用域限制

分两个阶段：

```text
严格保护期：now - foregroundSince <= launchWindowMs（默认 8000ms）
延迟等待期：严格期结束后，到 now - foregroundSince <= 30000ms 为止

两个阶段都要求：
  当前前台包名 == 来源包名
  当前包名不在跳转目标名单
  本次启动尚未成功点击
```

严格期内按完整规则匹配（包括「关闭 / ×」和右上角兜底）。延迟等待期内仍继续扫描，但只接受明确写着「跳过 / 关闭广告」的按钮，避免用户已经正常使用 App 后误点泛化关闭按钮。误触返回仍只在严格保护期内判定，不受延迟等待期影响。

### 3.3 节点遍历

```java
void walk(node, depth, state) {
    if (depth > 24 || nodes >= 2200) return;
    label = text + " " + contentDescription;
    n = normalize(label);
    if (hasAdMarker(n)) state.adMarker = true;
    if (isSkip(n) || isCloseAd(n) || isExactClose(n)) {
        if (visible && enabled && usableBounds) {
            score = ...
            state.candidates.add(...)
        }
    }
    for child in node.children: walk(child, depth + 1, state)
}
```

限制上限是为了防止某些页面（长列表、WebView）导致主线程卡顿。扫描在无障碍服务的主线程执行，通常几毫秒到几十毫秒。

### 3.4 文案规则

`Rules.normalize`：

- 转小写；
- 去掉空格、换行、制表符；
- 全角括号转半角。

`Rules.isSkipText`：

```text
包含 跳过 / 跳過
或 equals skip / startsWith skip / 包含 skipad
```

`Rules.isCloseAdText`：

```text
关闭广告 / 關閉廣告 / 关闭此广告 / closead / dismissad
```

`Rules.isExactClose`：

```text
关闭 / 關閉 / close / dismiss / × / x / ✕ / ✖ / ╳ / ✗ / ✘
```

只有页面出现过「广告 / 推广 / 赞助 / 跳过 / skip」等标记，**且仍处于严格保护期**时，才允许用「关闭 / ×」这类泛化按钮，降低误点风险。延迟等待期只接受「跳过」和「关闭广告」这类明确文案。

### 3.5 评分

| 条件 | 分值 |
|---|---|
| 含「跳过」 | 110 |
| 含「关闭广告」 | 85 |
| 泛化关闭 / × | 50 |
| 位于屏幕右上 55% 宽度、35% 高度区域 | +12 |
| 节点自身可点击 | +8 |
| 文本长度 ≤ 8 | +4 |
| 面积超过屏幕一半 | −25 |

取得分最高者。`isSkip` 候选优先于泛化关闭候选。

### 3.6 点击策略

1. 节点自身 `isClickable()` → `performAction(ACTION_CLICK)`。
2. 向上最多 8 层找可点击祖先。
3. 都失败 → `dispatchGesture` 在节点矩形中心点按（45ms）。
4. 仍然失败 → 不记录统计。

点击成功后：

- `handledPkg = 当前包名`，本次启动不再扫描；
- 写入 `events`；
- 可选 Toast（默认开）。

### 3.7 重试

如果没找到候选：

- 严格期内约 1.1 秒后再扫，延迟等待期约 0.9 秒后再扫；
- 最多 45 次，且总时长不超过 30 秒；
- 或页面切换到别的包；
- 或本次启动已成功点击。

这能覆盖「广告延迟加载」「倒计时从 5 秒变 0 秒后可点」的情况。

针对「百度网盘」这类先显示长时间 Logo 的 App，还做了一项关键处理：同一个包内 `TYPE_WINDOW_STATE_CHANGED` 的窗口类名发生变化（Logo Activity → 广告 Activity）时，把扫描次数重置为 0（1.5 秒内最多重置一次，防止弹窗抖动导致频繁复位），并立即安排一次扫描。否则 Logo 页可能在广告出现前就把重试次数用完。初始实现只有 10 次、8 秒，这是漏跳的直接原因。

### 3.8 为什么不做 OCR

- 需要 `takeScreenshot`（Android 11+）或 MediaProjection；前者有频率限制，后者每次要用户授权，无法开机自动。
- 离线 OCR 增加包体、内存、耗电和延迟。
- 截屏隐私敏感度高。
- 本版优先做可解释、低权限、低耗电的节点方案。

## 4. 误触跳转返回实现

### 4.1 状态

```java
String foregroundPkg;
long foregroundSince;
String lastInteractionPkg;
long lastInteractionAt;
String lastBlockedTarget;
long lastBlockedAt;
long suppressSplashUntil;
```

### 4.2 前台切换

```text
收到 WINDOW_STATE_CHANGED(pkg):
  if pkg == 桌面包名:
      foregroundPkg = null        // 从桌面打开目标 App 不算误触
      return

  if pkg == 自己 / 系统 UI / 输入法:
      return

  if pkg != foregroundPkg:
      previous = foregroundPkg
      foregroundPkg = pkg
      foregroundSince = now
      if pkg in 目标名单 && shouldBlock(previous, pkg):
          blockJump(previous, pkg)
```

### 4.3 判定条件

```text
previous != null
previous 不是目标 App
previous 不是桌面/输入法/系统 UI
maxAge = onlyDuringLaunch ? launchWindowMs : jumpWindowMs
now - previousSince <= maxAge
如果 onlyDuringLaunch：
    只要求在来源 App 的启动保护期内
否则：
    最近 2.5 秒内有来自 previous 的点击，或 previous 停留时间 <= 1.5s
距上次拦截同一个目标 > 2.5s
```

默认 `onlyDuringLaunch = true`，这是保守策略：只在来源 App 刚打开的前 8 秒内拦截，主要覆盖开屏页误触和摇晃跳转。关闭后会在更宽的时间窗内按「最近点击」判断，但更容易误拦用户主动打开的链接。

### 4.4 返回动作

```text
记录事件（归属来源 App，detail=目标 App 名称）
→ 220ms 后 performGlobalAction(GLOBAL_ACTION_BACK)
→ 850ms 后如果当前仍是目标包名，再 BACK 一次
```

为什么要两次：
- 第一次可能只关闭目标 App 的广告 Activity，仍停留在目标 App；
- 第二次才退出目标 App；
- 如果是浏览器，第一次可能是站内后退，第二次才退出。

为什么不能保证：
- 目标 App 可能拦截返回键；
- 浏览器可能把返回用于站内历史；
- 任务栈可能被广告 SDK 改写，返回后到桌面；
- 部分 App 使用 `moveTaskToBack` 等行为。

### 4.5 防误判

- 桌面事件会清空来源。
- 来源是目标 App 时不拦截（避免淘宝→京东链式跳转）。
- 同一目标 2.5 秒冷却。
- 返回后 2.5 秒内暂停开屏扫描（`suppressSplashUntil`）。
- 默认只在来源 App 启动保护期内拦截。
- 目标名单由用户可编辑，默认只含常见购物/浏览器/应用商店/短视频。

## 5. 统计设计

### 5.1 表

见 `README.md` 的 `events` 表。关键字段：

- `package_name`：**来源 App**（发生开屏广告或误触的 App）。
- `kind`：`SKIP` / `CLOSE` / `JUMP`。
- `target_package`：仅 `JUMP` 使用，记录落地 App。
- `detail`：`JUMP` 时是目标 App 名称；开屏时是命中的按钮文字。
- `created_at`：毫秒时间戳。

### 5.2 聚合

```sql
SELECT package_name,
       MAX(app_label),
       COUNT(*) AS total,
       SUM(created_at >= todayStart) AS today,
       SUM(kind = 'JUMP') AS jumps,
       MAX(created_at) AS last_at
FROM events
GROUP BY package_name
ORDER BY total DESC, last_at DESC
LIMIT 200;
```

首页展示：

- 总拦截数、今日、误触返回数、覆盖 App 数。
- 每个 App：总次数、今日次数、开屏/误触拆分、最近时间。
- 点击某行：最近 12 条明细，支持单独清除。

### 5.3 清理

- 启动时删除 180 天前记录。
- 首页「清空」删除全部。
- 详情弹窗「清除此 App 记录」删除单包。

### 5.4 线程

`StatsDb` 操作在 UI 线程执行。数据量上限 200 行、单次查询毫秒级；如果未来记录量增大，应改为 `ExecutorService` + 主线程回调。

## 6. 设置

`Prefs` 使用一个 SharedPreferences 文件：

| Key | 默认 | 说明 |
|---|---|---|
| `master_enabled` | true | 守护总开关；关闭后不再执行动作，统计保留 |
| `splash_enabled` | true | 开屏跳过 |
| `jump_enabled` | true | 误触返回 |
| `jump_only_during_launch` | true | 只在开屏期拦截 |
| `show_toast` | true | 拦截后轻提示 |
| `corner_fallback` | false | 右上角兜底 |
| `foreground_watchdog` | true | 常驻通知 |
| `launch_window_ms` | 8000 | 3–15 秒；之后仍有最长 30 秒的明确文案等待期 |
| `click_delay_ms` | 200 | 0–800 毫秒 |
| `jump_window_ms` | 3500 | 关闭「仅开屏期」后使用的跳转窗口，1.2–8 秒 |
| `jump_targets` | 内置名单 | 用户可编辑 |

无障碍服务注册 `OnSharedPreferenceChangeListener`，设置改变后立即生效，不需要重启服务。

## 7. 开机与保活

### 7.1 无障碍服务

Android 的无障碍服务由 `AccessibilityManagerService` 管理。用户开启后，系统在开机、应用更新、进程死亡后通常会重新绑定。因此**不需要**为了「开机运行」而常驻一个前台服务。

### 7.2 前台通知服务

`GuardForegroundService`：

- `specialUse` 类型（Android 14+）。
- 低优先级、持续、无声音通知。
- 每 60 秒检查无障碍状态，更新「守护中 / 未开启」。
- `START_STICKY`。
- 只负责提升进程优先级和显示状态，不执行拦截逻辑。

### 7.3 广播

`BootReceiver`：

- `BOOT_COMPLETED`：开机后，如果守护开启且无障碍已启用，启动通知服务。
- `MY_PACKAGE_REPLACED`：应用更新后恢复。
- 部分 ROM 的 `QUICKBOOT_POWERON`。

### 7.4 无法保证的部分

- 强行停止后，系统不会派发广播，应用无法自启。
- 厂商省电策略可能冻结进程；需要用户白名单。
- Android 15+ 对后台启动前台服务更严格，失败时静默降级（不崩溃）。
- 用户关闭无障碍后，任何代码都无法重新开启。

## 8. 隐私与安全

- 没有 `INTERNET` 权限，无法发起网络请求。
- 不保存截图、不保存完整页面。
- `detail` 只保存命中的按钮文字（如「跳过」「关闭广告」）或目标 App 名称。
- 数据库和 SharedPreferences 都是应用私有目录。
- `allowBackup="false"`，避免云备份把统计带走。
- 不申请悬浮窗、使用情况访问、通知读取。
- `QUERY_ALL_PACKAGES` 只用于读取应用名称/图标。

### 9.1 手工功能测试

## 10. 后续可增强

1. **本机 OCR 增强**：`AccessibilityService.takeScreenshot` + 离线中文 OCR，显式开关，只处理开屏保护期。
2. **按 App 规则**：为每个 App 单独设置保护时长、是否启用、自定义按钮文案。
3. **规则云端更新**：需要联网，和当前「无网络权限」定位冲突，谨慎。
4. **统计图表**：7 日趋势、时段分布。
5. **导出/导入**：本地 JSON，用户主动分享。
6. **Shizuku/root 模式**：更强的前台/输入控制，但门槛高，不作为默认。
