# 清屏（QingPing）

> 一款本地运行的 Android 开屏广告跳过 / 误触跳转返回工具。  
> 无联网权限，统计只保存在本机。

清屏通过 Android **无障碍服务（AccessibilityService）** 读取当前窗口中的按钮文字，自动点击「跳过」「关闭广告」；当从其他应用突然跳到购物 App、浏览器或应用商店时，尝试按返回键回到原应用。拦截次数按来源 App 记录，可在应用内查看。

> **v1.0.1**：修复「百度网盘」等 App 先显示长时间 Logo、之后才出现开屏广告时，8 秒保护期已过而漏跳的问题。现在保护期后还会继续等待最多 30 秒，并在 Logo 页切换到广告页时重置扫描次数；后段只点击明确的「跳过 / 关闭广告」，不扩大泛化关闭按钮的误点范围。

## 一、可做与不可做

Android 没有向普通应用开放「全局拦截触摸 / 阻止 Activity 启动」的能力。清屏的做法是**在广告出现后尽快点击跳过**，以及**在误触跳转发生后尽快返回**，不是网络层广告拦截，也不是点击前拦截。

| 能力 | 是否实现 | 说明 |
|---|---|---|
| 自动点击「跳过 / 关闭广告」 | ✅ | 需要按钮在无障碍树中暴露文字、contentDescription，或存在可点击节点 |
| 纯图片 / 自绘 / 未暴露节点的广告 | ❌ | 当前版本不截图、不做 OCR，因此可能找不到按钮 |
| 按 App 统计拦截次数 | ✅ | 记录来源 App、类型、时间；点击列表可看最近记录 |
| 误触跳转后自动返回 | ✅（尽力而为） | 目标页面会先出现，再执行返回；无法在启动前阻止 |
| 摇晃 / 传感器触发的跳转 | ⚠️ | 无法阻止传感器事件，只能在跳转发生后尝试返回 |
| 拦截应用内 Banner、信息流、视频广告 | ❌ | 不在开屏保护窗口内，不处理 |
| 网络层去广告 | ❌ | 本版不实现 VPN / DNS 过滤；避免与系统 VPN 冲突 |
| 开机后自动恢复 | ⚠️ | 无障碍服务由系统重新绑定；另提供开机广播 + 可选常驻通知。需要用户允许自启动/电池白名单 |
| 被「强行停止」后自动恢复 | ❌ | Android 禁止任何应用在被强行停止后自行启动，必须重新打开清屏 |
| 自动开启无障碍服务 | ❌ | 必须由用户在系统设置中手动开启，应用无法代劳 |
| 上架 Google Play | ❌（不建议） | 使用无障碍 API 做广告跳过通常不符合商店政策，建议侧载 |

### 关键限制

1. **不能提前拦截跳转。** 无障碍服务只能在目标 Activity 已经启动后收到窗口变化事件，然后按返回键。因此会看到目标 App 一闪而过，返回也不一定 100% 成功。
2. **不能保证点到每一个跳过按钮。** 广告可能使用 `FLAG_SECURE`、WebView 不暴露节点、Canvas 自绘、图片按钮或动态混淆文字。
3. **不能阻止广告加载。** 只处理展示后的跳过按钮，不修改其他应用的网络请求。
4. **不能保证所有 ROM 都不杀后台。** 无障碍服务通常比普通后台进程更耐活，但小米、华为、OPPO、vivo 等仍需手动允许自启动和关闭电池限制。
5. **无障碍服务能看到屏幕文字。** 这是能力的来源，也是隐私风险。清屏没有 `INTERNET` 权限，只把命中的按钮文字、来源包名和时间写入本地 SQLite；不保存截图，不上传数据。

## 二、安装与首次配置

### 环境要求

- Android 8.0（API 26）及以上
- 建议 Android 11 及以上
- APK：`清屏-v1.0.1-debug.apk`（调试签名，适合自用/侧载）

### 步骤

1. 安装 APK。Android 13+ 如果提示「受限设置」，先进入 **应用信息 → 右上角 ⋮ → 允许受限设置**。
2. 打开清屏，点击「去开启」，在系统无障碍列表中找到 **清屏**，开启 **清屏守护**。
3. 返回清屏，状态应显示「守护中」。
4. 点击「电池优化 → 去设置」，允许清屏忽略电池优化。
5. 点击「开机与后台 → 查看」，按手机品牌允许自启动/后台运行：
   - 小米：安全中心 → 应用管理 → 权限 → 自启动
   - 华为：手机管家 → 应用启动管理 → 清屏 → 手动管理
   - OPPO / 一加：设置 → 应用管理 → 自启动
   - vivo：i管家 → 应用管理 → 权限管理 → 自启动
   - 三星：设置 → 电池 → 后台使用限制
6. 打开一个带开屏广告的 App 测试。首次命中后，清屏首页会出现该 App 的统计。

> 如果系统提示「无障碍服务会读取屏幕内容」，这是 Android 的标准提示。清屏没有联网权限，数据不会离开设备。

## 三、使用说明

### 首页

- **守护中 / 未开启**：当前无障碍服务状态。
- **已为你清屏**：累计成功动作数；下方分别是今日、误触返回、覆盖 App 数。
- **按 App 统计**：按来源 App 聚合。点某一行可查看最近 12 条记录，并可单独清除该 App 的记录。
- **开屏广告自动跳过**：总开关之一，关闭后不再扫描开屏页。
- **误触跳转自动返回**：总开关之一，关闭后不再执行返回。
- **更多设置**：守护总开关、启动保护时长、点击延迟、跳转名单、后台通知等。

统计口径：

- **开屏**：成功点击了「跳过」或「关闭广告」。
- **误触**：检测到从来源 App 跳到目标 App，并执行了返回。
- 一条误触记录归属于**发生误触的来源 App**，详情里显示跳转目标（如「误触返回 → 淘宝」）。

### 更多设置

- **启用清屏守护**：总开关。关闭后保留统计，但不再执行开屏跳过和误触返回。
- **启动保护时长**：应用切换后，在这段时间内按完整规则识别开屏广告，默认 8 秒。调小更保守。超过这段时间后，清屏仍会为「百度网盘」这类先显示长时间 Logo 的 App 继续等待最多 30 秒，但只点击明确写着「跳过 / 关闭广告」的按钮，不再点击泛化的「关闭 / ×」，也不执行右上角兜底。
- **点击延迟**：检测到按钮后等待多久再点击，默认 200 ms。
- **右上角兜底点击**：危险选项，默认关闭。只有页面出现「广告/跳过」文字但找不到可点击节点时，才尝试点右上角；可能误点应用内按钮。
- **仅在开屏保护期内拦截**：默认开启。只在来源 App 刚打开的前 N 秒内拦截跳转，减少把正常链接跳转误判为广告。
- **跳转拦截名单**：默认包含常见购物、浏览器、应用商店、短视频 App。可搜索并勾选/取消；只对名单内目标生效。
- **常驻守护通知**：低优先级通知，提升进程优先级并显示状态。关闭后仍有无障碍服务，但后台存活能力下降。
- **清空全部统计**：只删记录，不改设置。

## 四、实现方案

### 4.1 组件

```text
┌────────────────────────────┐
│ MainActivity / Settings    │
│ 状态、统计、规则、名单       │
└─────────────┬──────────────┘
              │ SharedPreferences / SQLite
┌─────────────▼──────────────┐
│ AdGuardService              │
│ AccessibilityService        │
│  ├─ 前台包名跟踪             │
│  ├─ 开屏节点扫描/点击        │
│  └─ 误触跳转检测/返回        │
└─────────────┬──────────────┘
              │
┌─────────────▼──────────────┐
│ StatsDb (SQLite, 本地)      │
└────────────────────────────┘

BootReceiver ──► GuardForegroundService（可选常驻通知）
```

### 4.2 开屏跳过

1. 监听 `TYPE_WINDOW_STATE_CHANGED` / `TYPE_WINDOW_CONTENT_CHANGED`。
2. 在前台 App 切换后的「启动保护时长」内按完整规则扫描，避免影响正常页面。
3. 超过保护时长后进入**延迟广告等待期**（最长 30 秒）：继续低频率扫描，但只接受明确写着「跳过 / 关闭广告」的按钮；泛化的「关闭 / ×」和右上角兜底只在保护期内可用。
4. 从 `getRootInActiveWindow()` 做有上限的广度/深度遍历（最多 2200 个节点、24 层）。
5. 识别文字 / contentDescription：
   - 高优先级：`跳过`、`跳過`、`skip`、`跳过广告`
   - 中优先级：`关闭广告`、`close ad`
   - 低优先级：页面出现广告标记时，`关闭`、`×`、`X` 等
6. 评分时优先右上角、可点击节点、短文本。
7. 先尝试 `ACTION_CLICK`；如果节点/祖先都不可点击，用 `dispatchGesture` 在节点中心点按。
8. 成功后记录统计，并在本次启动内停止继续扫描，避免连续误点。
9. 如果没找到，按约 1.1 秒（等待期约 0.9 秒）重试，直到 30 秒或 45 次上限。
10. 同一个 App 内切换到新的 Activity（Logo 页 → 广告页）时重置重试预算，避免在 Logo 页把次数用完。

### 4.3 误触返回

1. 维护 `foregroundPkg` 和进入时间。回到桌面时清空来源，避免把「从桌面正常打开淘宝」当成误触。
2. 当新前台包名属于目标名单：
   - 来源必须是普通 App（不是桌面、输入法、系统 UI、另一个目标 App）；
   - 来源停留时间在跳转窗口内；
   - 默认还必须在来源 App 的开屏保护期内；
   - 距离上次拦截同一目标超过 2.5 秒。
3. 满足条件时记录到**来源 App**，延迟约 220 ms 执行 `GLOBAL_ACTION_BACK`。
4. 约 850 ms 后如果当前仍是目标包名，再执行一次返回。
5. 返回后 2.5 秒内暂停开屏扫描，避免刚回到来源 App 就误点。

> 这就是「能实现」和「受限制」的核心差别：系统只允许事后返回，不允许事前拦截。

### 4.4 统计

表结构：

```sql
CREATE TABLE events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  package_name TEXT NOT NULL,      -- 来源 App
  app_label TEXT NOT NULL,
  kind TEXT NOT NULL,              -- SKIP / CLOSE / JUMP
  target_package TEXT,             -- JUMP 时的目标
  detail TEXT,                     -- 按钮文字或目标名称
  created_at INTEGER NOT NULL
);
```

- 首页按 `package_name` 聚合，展示总数、今日、开屏/误触拆分、最近时间。
- 明细只保留最近 12 条在弹窗中展示。
- 数据保留 180 天，启动时清理过期记录。

### 4.5 开机与保活

- **无障碍服务本身**：只要用户在系统设置中保持开启，系统会在开机后重新绑定，不依赖清屏进程一直活着。
- **BootReceiver**：收到 `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` 后，如果守护开启且无障碍已启用，启动可选的常驻通知服务。
- **GuardForegroundService**：`specialUse` 类型前台服务，低优先级通知，`START_STICKY`，每 60 秒更新状态。
- **电池优化**：通过系统对话框请求忽略电池优化。
- **厂商自启动**：没有统一 API，只能引导用户到各 ROM 的设置页。

## 五、构建

项目使用 Java + 平台控件，无 AndroidX、无第三方运行时依赖。

```bash
# 需要 JDK 17+、Android SDK Platform 34、Build Tools 34.0.0
./gradlew assembleDebug
```

Windows：

```powershell
$env:JAVA_HOME='C:\Program Files\Java\jdk-17'
.\gradlew.bat assembleDebug
```

产物：

```text
app/build/outputs/apk/debug/app-debug.apk
```

项目内已带 Gradle Wrapper。首次构建需要网络下载 Android Gradle Plugin 和依赖；之后可离线构建。

## 七、隐私

- **没有声明 `android.permission.INTERNET`**，代码层面无法发起网络请求。
- 不申请悬浮窗、UsageStats、通知读取等额外权限。
- 不保存截图、不保存完整页面文本；统计里只保存命中的按钮文字（如「跳过」）和 App 名称。
- 卸载应用即删除本地数据库和设置。

## 八、已知问题

1. **纯图片开屏**：无障碍树没有文字时无法识别。后续可选的增强方案是本机 OCR（`AccessibilityService.takeScreenshot` + 离线文字识别），但会增加耗电、延迟和隐私敏感度，本版未启用。
2. **WebView 广告**：部分 App 的 WebView 不向无障碍服务暴露内部 DOM，只能识别外层容器。
3. **返回失败**：目标 App 可能消费返回键、跳到浏览器站内历史，或因任务栈被修改而回到桌面。
4. **误判**：在保护期内主动点击外部链接，也可能被当成误触返回。可关闭「误触跳转自动返回」或缩小保护时长。
5. **厂商杀后台**：被系统「强行停止」后无法自启；这是 Android 的设计，不是本项目能绕过的限制。
6. **调试签名**：仓库产物使用 debug 签名，仅适合个人侧载。正式分发请生成自己的 release keystore。
